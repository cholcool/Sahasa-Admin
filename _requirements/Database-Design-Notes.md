## 2. สิ่งที่รู้แล้ว (ยืนยันแล้ว)

- **บัญชีชำระ A / B ใน AppSheet = ประเภทบิล VAT / NOVAT** (ไม่ใช่บัญชีธนาคาร)
  - A = VAT: ออเดอร์ที่ขอใบกำกับภาษี 255 จาก 256 รายการเป็น A
  - B = NOVAT: ออเดอร์ที่ขอบิลเงินสดเป็น B ทั้งหมด
  - ออเดอร์ Marketplace เป็น B ทั้งหมด ส่วน Line/Facebook เป็น A เกือบทั้งหมด
- ร้าน Shopee: `khlongngaetofu` เงินโอนเข้าบัญชี บจก.สหัสา (กสิกรไทย)
- ทุก Marketplace ส่งของเอง (Seller Own Fleet / Dropshipping) ไม่ได้ใช้ขนส่งของ platform

**จากคำตอบลูกค้าและ SRS ฉบับอัปเดต (2026-11-18)** และผลต่อการออกแบบ
| เรื่อง | คำตอบ | ผลต่อ database |
|---|---|---|
| สินค้า (Q1) | มี 2 รายการ อนาคตอาจเพิ่ม ราคาและค่าส่งต่างกันตาม platform | `products` เพิ่มได้ไม่จำกัด + `price_tiers` และ `shipping_fees` แยกตามช่องทาง |
| ตัดรอบ (Q8) | เที่ยงทุกวัน ออเดอร์ตั้งแต่ 13:00 วันก่อน ถึง 10:00 วันนี้ อยู่รอบเที่ยงวันนี้ | `delivery_rounds` เก็บเวลาเริ่ม/สิ้นสุดรับออเดอร์ของรอบ (ยังต้องถามช่วง 10:00–13:00) |
| ส่งไม่ครบ (SRS 26) | แอดมินส่งใหม่ เพิ่มเลข tracking ใน Order เดิม | `shipments` 1 Order : หลาย shipment |

## 4. ข้อค้นพบจากไฟล์ Marketplace

### สินค้าและราคา (จาก Shopee / Lazada)
- **เต้าหู้คลองแงะ เนื้อคัสตาร์ด** แพ็ค 10 ชิ้น 2 kg
  - ⚠️ "แพ็ค 10 ชิ้น" เป็นแค่ชื่อ listing บน Shopee ในระบบ**นับและคิดราคาเป็นชิ้น**ทุกช่องทาง (ชีต `ราคาสินค้าและค่าขนส่ง`: บาท/ชิ้น, ชุด, ครั้ง) SKU บน platform แปลงเป็นชิ้นด้วย `sku_mappings.units_per_sku`
  - Shopee: ราคาตั้ง 350 ลดตามจำนวน (2 แพ็ค = แพ็คละ 300, 10 แพ็ค = แพ็คละ 280)
  - Lazada: 450 (รวมค่าส่ง +50 ที่ใส่เป็นตัวเลือกสินค้า)
- **น้ำจิ้มมะขามน้ำตาลตะโหนด** 400g ราคา 75 บาท (ขายแยก ไม่ใช่ของแถม)
- Shopee: ผู้ซื้อจ่ายค่าส่ง 150 บาท (บางออเดอร์ 30)

### Shopee Order export
- 1 บรรทัดต่อสินค้า แต่ยอดระดับออเดอร์ (ค่าคอม, ยอดรวม) ซ้ำอยู่ทุกบรรทัด → ต้องระวังไม่นับซ้ำตอนนำเข้า
- **ช่อง SKU ว่างทั้งหมด** → ควรตั้ง SKU ใน Shopee ก่อนทำการจับคู่อัตโนมัติ
- เบอร์โทรอยู่ในรูปแบบ `66xxxxxxxxx`

### Shopee Income (รายรับ ก.ย.)
- 3 ชีต: Summary / Income (1 แถวต่อออเดอร์) / Adjustment
- ยอดโอนทั้งเดือน **434,030 บาท** (ยอดขาย 475,700 ส่วนลดฝั่งร้าน −51,789 ค่าส่ง +101,160 ค่าธรรมเนียม −91,060)
- ค่าธรรมเนียมแยกเป็น: ค่าคอมมิชชั่น, ค่าคอม AMS (affiliate), ค่าธุรกรรมการชำระเงิน, ค่าธรรมเนียมโครงสร้างพื้นฐาน
- มีรายการปรับปรุง: คืนเงินหลังออเดอร์สำเร็จ −427 บาท
- **ความน่าเชื่อถือของไฟล์**:
  - ตัวเลขข้างในตรงกันทั้งหมด (ผลรวมทุกคอลัมน์ ยอดรายออเดอร์ และหน้า Summary)
  - แต่ไฟล์ถูกเปิดและบันทึกใหม่ด้วย Excel Online เมื่อ 10 พ.ย. จึงยืนยันจากไฟล์อย่างเดียวไม่ได้ว่าไม่ถูกแก้
  - วิธียืนยัน: เทียบยอด 434,030 บาทกับ statement ธนาคาร หรือกับข้อมูลจาก API

### Lazada

## 5. แนวทางออกแบบ Database (ร่าง ยังไม่ final)

### หลักการ
- **MariaDB ของ Hostinger** (✅ ตัดสินใจแล้ว 2026-11-13 ดูข้อปรับสำหรับ MariaDB ในหัวข้อ 5.2)
- เงินใช้ `DECIMAL(12,2)` เวลาใช้ `DATETIME(3)` เก็บเป็น UTC (แสดงผลเป็น Asia/Bangkok)
- เก็บคอลัมน์ร่วมตามร่างเดิม: `created_date/by`, `updated_date/by`, `is_deleted`
  - `created_by` ต้องรองรับออเดอร์ที่ระบบสร้างเอง (สร้าง user "system")
- ใช้คอลัมน์ `version` กันการแก้ไขชนกัน
- เอกสารบัญชีห้ามลบ ถ้าผิดให้ยกเลิกแล้วออกใบลดหนี้

### สิ่งที่ต้องแก้จากร่างเดิมในชีต Database
1. เลิกใช้คอลัมน์แยกตามสินค้า (`tofu_quantity`, `sauce_quantity`) → `order_items` เก็บสินค้าละ 1 แถว
2. `channel`, `carrier` จาก VARCHAR → ตาราง master + FK
3. เพิ่ม `platform_order_no` + UNIQUE `(channel_id, platform_order_no)` สำหรับกันออเดอร์ซ้ำ
4. เพิ่มสถานะ: `status`, `payment_status` + ตารางประวัติสถานะ
5. แยก `order_date` กับ `ship_date` / รอบส่ง
6. แยกยอดเงิน: `subtotal`, `seller_discount`, `platform_discount`, `shipping_fee_buyer`, `total_paid`
7. "บัญชีชำระ" → `bill_type` (VAT/NOVAT) ตั้งค่าเริ่มต้นตามช่องทางแล้วแก้รายออเดอร์ได้
8. ข้อมูลใบกำกับภาษี → ตาราง `customer_tax_profiles` แทนการเขียนในหมายเหตุ

### รับข้อมูลได้ทั้ง Upload ไฟล์ และ API (ใช้ขั้นตอนเดียวกัน)

```
[อัปโหลด Excel] ─┐
                 ├─> import_batches ─> platform_raw_records (JSONB) ─> แปลงข้อมูล ─> UPSERT orders / settlements
[Shopee API]   ──┘    (ที่มา: file/api, hash ของไฟล์)                  key = (platform, platform_order_no)
```

- กันอัปโหลดไฟล์ซ้ำด้วย hash ของไฟล์
- อ่านไฟล์โดยหาคอลัมน์จาก**ชื่อหัวคอลัมน์** ไม่ใช่จากตำแหน่ง และตรวจยอดรวมก่อนนำเข้า
- ข้อมูลที่ platform เป็นเจ้าของ (สถานะ, ยอดเงิน, ค่าธรรมเนียม): ข้อมูลจาก API ทับข้อมูลจากไฟล์
- ข้อมูลภายในบริษัท (รอบส่ง, หมายเหตุภายใน, ประเภทบิล): ไม่ถูกทับไม่ว่าจะมาทางไหน

    → ต้องถามต่อ: จำนวนผู้ใช้ และสิทธิ์เริ่มต้นของแต่ละ Role (เช่น ใครแก้ราคาได้ ใครเห็นยอดเงินได้)
