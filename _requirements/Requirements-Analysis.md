## 1. ภาพรวมระบบ

ระบบหลังบ้านสำหรับ **รวมออเดอร์จากทุกช่องทางการขายไว้ที่เดียว** แล้วส่งต่อไปยังโรงงานเพื่อผลิต/จัดส่ง และส่งข้อมูลต่อให้ฝ่ายบัญชี

**ช่องทางการขาย**
- Marketplace (ดึงผ่าน API): Shopee, TikTok Shop, Lazada
- Manual (คีย์เองหรือ Upload Template): Line, Facebook, หน้าร้าน, โทร

**ขนส่ง**: Inter Express (หาดใหญ่), Nim Express (กทม.), Fuze Express (กทม.), ส่งจากหน้าร้าน, รถตู้/รถทัวร์

**ผู้ใช้งาน (Role)**

| Role | หน้าที่หลัก |
|---|---|
| System | งานอัตโนมัติ: ดึง API, กันออเดอร์ซ้ำ, Audit log |
| Admin | ตั้งค่า SKU mapping, ดู API log/Re-sync, เพิ่มออเดอร์หลังตัดรอบ |
| Sales | คีย์/อัปโหลด/ยืนยัน/แก้ไข/ยกเลิกออเดอร์ |
| หัวหน้า | เพิ่มออเดอร์หลังตัดรอบ (FR12) |
| Owner | ดูแดชบอร์ด |
| โรงงาน | รับออเดอร์, สรุปยอดผลิต, พิมพ์เอกสาร, อัปเดตการจัดส่ง |
| บัญชี | รับรู้รายได้, ออกบิล/ใบกำกับภาษี, กระทบยอด, รายงาน |

## 2. Workflow ของออเดอร์ (สรุปจาก FR)

```
[รับออเดอร์]                 [ตรวจสอบ]            [โรงงาน]                    [จัดส่ง]                [บัญชี]
API Marketplace ─┐
Upload Template ─┼─> กันซ้ำ / Map SKU ─> ตรวจ & ยืนยัน ─> คิวตามรอบตัด+ขนส่ง ─> พิมพ์ใบจัด/ใบปะหน้า ─> Tracking ─> จัดส่งสำเร็จ
คีย์ Manual ─────┘    (flag ถ้า map ไม่ได้)  (ทีละรายการ/Bulk)  "รับ Order" + สรุปยอดผลิต                 sync กลับ platform
                                              │
                                              └─> รับรู้รายได้ / ออกบิล VAT-NOVAT ─> กระทบยอดเงินโอน Marketplace
ยกเลิก (พร้อมเหตุผล) ได้ทุกช่วง; ถ้าโรงงานรับแล้วต้องแจ้งเตือนโรงงาน; หลังออกบิลต้องออกใบลดหนี้
```

**สถานะที่น่าจะต้องมี (อนุมานจาก FR ยังไม่มีในเอกสาร ควรยืนยัน)**
`รอตรวจสอบ` → `ยืนยันแล้ว` → `โรงงานรับแล้ว` → `จัดส่งแล้ว` → `จัดส่งสำเร็จ` และ `ยกเลิก`, `ล่วงหน้า (รอรอบส่ง)`, `ส่งไม่ครบ`

**ยังต้องแก้หรือยืนยัน**
1. **SRS 19 รวม 2 requirement ไว้ในข้อเดียว** (Upload Template + ตรวจ Order ซ้ำ) และการตรวจซ้ำซ้ำกับ SRS 43 ควรแยก Upload ไว้ข้อเดียว แล้วให้การตรวจซ้ำอยู่ที่ SRS 43
2. **SRS 19 ขัดกันเอง**: เขียนว่า "เลขที่ Order ของ Platform … จะต้องส่งมาเสมอ" แต่หมายเหตุบอกว่ายังรอเกณฑ์ตรวจซ้ำของ Order Manual หรือ Upload ที่ไม่มีเลข Platform ต้องตกลงว่า Order จาก Line/Facebook/หน้าร้าน/โทร ต้องมีเลขอ้างอิงหรือไม่ ถ้าไม่มี จะตรวจซ้ำอย่างไร
3. **SRS 47 Re-sync**: เขียนกำกวม ("ครล" น่าจะเป็น "ครบ") ต้องยืนยันว่าช่วงห่างคือ 10 / 20 / 30 นาที ใช่ไหม และเมื่อกดเองครบ 2 ครั้งแล้วยังไม่สำเร็จ จะทำอย่างไรต่อ
4. **SRS 26 ส่งไม่ครบ**: รายละเอียดบอกว่าแอดมินส่งใหม่ แต่หมายเหตุยังบอกว่ารอยืนยันว่าส่งรอบหน้าหรือคืนเงิน ควรอัปเดตหมายเหตุให้ตรงกัน
5. **SRS 25 พูดถึง "รายการเคลื่อนไหว"** แต่ SRS 59 ยังว่าง ต้องกำหนดว่าโมดูลนี้คือ timeline ของ Order / การจัดส่ง หรือคือสต็อก
6. **SRS 24, 25, 27** รายละเอียดขึ้นต้นด้วย "." เกินมา
7. **SRS 9 สถานะ Order** ยังเป็นร่าง ควรเพิ่มสถานะ "ส่งไม่ครบ" ด้วย เพราะ SRS 26 อนุญาตให้ 1 Order มีหลาย shipment
8. **SRS 1 session timeout** ยังไม่กำหนดเวลา
9. คอลัมน์ Sign off / Status / Dev ยังว่างทุกข้อ

**FR ยังไม่ได้อัปเดต** (เนื้อหาเหมือนเดิม): ยังมีคำผิด "Tamplate", "dot matix" และ FR26 ยังใช้ชื่อบุคคล "เฉิน" แทน Role

**คำถามค้างตอบ** → รวมไว้ที่ [Database-Design-Notes.md หัวข้อ 7](Database-Design-Notes.md)

## 7. ข้อเสนอแนะ

1. แยก SRS 19 ออกเป็น 2 ข้อ และตกลงเรื่องเลขอ้างอิงของ Order Manual
2. อัปเดตหมายเหตุของ SRS 26 และกำหนดความหมายของ SRS 59 ให้ตรงกับ SRS 25
3. ทำเอกสาร **Order Status Flow** (รวมสถานะส่งไม่ครบ) และ **Role–Permission Matrix** ตาม SRS 61
4. เพิ่ม FR ให้ SRS ที่ยังไม่มี FR รองรับ หรือให้ Owner sign-off scope
5. ปิดคำถามค้างตอบใน [Database-Design-Notes.md](Database-Design-Notes.md) ก่อนเริ่ม Dev โมดูล Order และ บัญชี
